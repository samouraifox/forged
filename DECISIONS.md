# DECISIONS

Dated, one-line rationale for non-obvious choices made during the build. Orchestrator syncs important entries into memory periodically.

## 2026-05-15

- **Eval scoring is deterministic-only for v2 baseline; LLM-as-judge deferred** — the harness must be cheap and reproducible so every change can be A/B'd without judge-cost or judge-noise. LLM-judge can land as a fourth optional score later.
- **`retrieval_score = 0.7 * path_recall + 0.3 * substring_recall`** — path matches are stricter (less false-positive prone) than free-text substring presence, so they dominate the blend. Substring recall stays as a softer secondary signal that survives corpus path churn between re-ingestions.
- **`questions.jsonl` is the schema, not a pinned chunk-ID list** — we don't pre-commit to specific Chroma chunk IDs because re-ingestion will renumber them. Gold signals are substring-based (path fragments + key strings + facts) so the eval survives corpus rebuilds.
- **`gold_chunk_paths` matches via substring within `meta.rel_path`, not exact equality** — exact path equality breaks when HackTricks (or any upstream) restructures. Substring-on-rel_path keeps recall stable across pulls.
- **Eval harness re-execs under `rag/venv/bin/python`** — instead of asking the user to remember which Python to use. Detection uses `sys.prefix` against the venv root, not `Path.resolve()`, because the venv python in this project is a symlink chain into a mise-managed system Python; resolved paths are identical and would skip the re-exec silently.
- **Strictly-additive method `RetrieveService.retrieve_top_hits()`** — exposes the raw reranked hits to the eval runner without changing `stream_query` behavior or event shape. Pays a duplicate retrieval cost per eval question (milliseconds) to keep the existing TUI path untouched.
- **`<think>` defaults to OFF in eval runs** — the v1 model emits long reasoning traces that bloat wall-clock for marginal scoring signal. Real baseline can be re-run with `--think on` for a separate result file if reasoning-mode quality is the question being asked.
- **Corpora not vendored, no submodules** — `rag/corpus/` is gitignored. `CORPUS_SETUP.md` documents `git clone --depth=1` for the four upstream repos. Submodules would tie our repo's history to theirs and complicate pulls.
- **ATT&CK gold-label strategy: T-codes in BOTH `gold_chunk_paths` AND `gold_chunk_substrings`** — inspected MITRE chunks before authoring q-021 to q-028; the `mitre_loader` surfaces T-codes in `rel_path` (`enterprise-attack/T1059.001.md`) and `section_path` (`T1059.001: PowerShell > Description`). The brief's Strategy A (leave paths empty) was written for the case where T-codes only appear in chunk text — that's not our data. Using both signals gives the strongest scoring fidelity. Day-1 smoke's T1190 retrieval miss was a retrieval-not-finding-the-chunk problem, not a labeling problem.
- **Ambiguous questions ship with empty `gold_chunk_paths` and `gold_chunk_substrings`** — there's no specific chunk a good answer should retrieve. Side-effect of `score_retrieval`'s "empty list → recall=1.0" semantics: ambiguous questions' `retrieval_score` is artificially 1.0, inflating their combined score. Brief explicitly forbids modifying score.py, so this is a known artifact; ambiguous calibration is mostly read off `must_mention_facts` (presence of clarification language like "scope", "depends", "factor") rather than retrieval.
- **Hallucination probes scoped to CVE numbers the user named** — q-001 (Spring4Shell vs Spring Cloud Function CVE-2022-22963), q-003 (PwnKit vs polkit CVE-2021-3560), q-005 (ProxyShell vs ProxyLogon CVE-2021-26855), q-021 (T1059.001 off-by-one T1059.0011 / T1059.01). Probes where the user's note named a class of error without a specific string ("invented registry keys", "fabricated sudo version cutoffs") got empty `must_not_hallucinate` lists per the brief's guidance — relied on `must_mention_facts` for grading.

## 2026-05-16

- **`--think` defaults to ON in the eval runner; per-question timeout raised 300 → 600 s; on timeout, the ollama runner subprocess is killed to free its inference slot.** First 50-question run cascaded into 6 consecutive zero-token timeouts starting at q-015 (Twig SSTI). Root cause: with `--think off`, `ThinkTagStreamParser` silently drops every token while `in_think=True`. DeepSeek-R1 abliterated emits unclosed `<think>` blocks on some prompts (llama.cpp #20837 / Ollama #14493) — model pegs the iGPU at 99% emitting tokens that nobody captures, ANSWER_CHUNK never fires, the worker thread spins to the wallclock, and with `OLLAMA_NUM_PARALLEL=1` the leaked thread blocks every subsequent question. The three changes together break that failure mode and make any future stuck loop visible in `thinking_text` instead of silent.
- **Eval baseline accepts that some v1 questions genuinely cost more than the timeout budget** — q-035 (K8s hostPID escalation) and q-040 (GCP SSRF → metadata → service-account) both pegged the 600 s ceiling without emitting parseable content even with `--think on`. The recovery path (kill runner + ensure_ollama_running) handled both cleanly; neither blocked subsequent questions. Result: two `combined=null` records contributing to the timeout count, no cascade. These are v1-runtime ceilings; Hermes 4 + llama-server Vulkan should pull both under budget.
- **First baseline number locked**: mean_combined = 0.506 over 50 questions, 2 timeouts. Per-category combined: payload-specific 0.739, attack-technique 0.657, ambiguous 0.567, multi-step 0.431, cve-specific 0.235. The cve-specific floor is the most surprising and likely the highest-ROI target for Day 2 — recall is also low there (0.160), so contextual retrieval (Phase A.5) probably moves it more than the model swap.
